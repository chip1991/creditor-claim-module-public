# Python 后端全量建设 Spec

## Why
当前工作区只有前端与需求文档，缺少可支撑“数据导入→清洗→AI分析→整改闭环→满意度校验→看板/报告→问答”的后端能力，无法完成端到端演示与验收。

## What Changes
- 新增 Python 后端工程（FastAPI + PostgreSQL + Redis + 异步任务）以覆盖需求文档中的全量后端能力。
- 新增统一的长任务体系（导入/清洗/分析/报告/导出/预警扫描），支持任务进度查询与 SSE 流式推送。
- 新增 RBAC + 数据范围 + 脱敏/明文开关 + 审计日志，覆盖需求文档的权限矩阵与审计要求。
- 新增与前端现有接口路径对齐的 REST API，并补齐文档要求的必要接口。

## Impact
- Affected specs: 数据导入/清洗/关联、投诉 AI 分析、人机协作与置信度策略、整改闭环状态机、满意度校验、预警与升级、看板指标、AI 问答、自动化报告、系统配置、权限与审计、通知中心。
- Affected code: 新增后端目录（建议 /workspace/backend）；前端不强制改动，但后端需对齐已存在的 API 路径（如 /data/page、/analysis/page、/workorder/create 等）。

## ADDED Requirements

### Requirement: 后端工程基础
系统 SHALL 提供一个 Python 后端工程，包含 API 服务、数据库访问层、异步任务系统与配置管理。

#### Scenario: 服务启动
- **WHEN** 运维启动后端服务
- **THEN** 服务对外提供 HTTP API，并具备健康检查端点可用于探活

### Requirement: 认证与权限（RBAC + 数据范围）
系统 SHALL 支持基于 Token 的认证，并实现客服专员/执行人员/部门管理者/集团管理层/系统管理员五类角色的页面与操作权限控制（需求文档 13.1/13.2），并支持部门数据范围隔离。

#### Scenario: 执行人员访问工单
- **WHEN** 执行人员请求工单列表
- **THEN** 仅返回其所属部门的数据

### Requirement: 数据脱敏与明文查看
系统 SHALL 对手机号、楼栋房号、原文等敏感字段默认脱敏；明文查看 SHALL 由系统管理员启用，并要求具备明文权限且写入审计（需求文档 13.4）。

#### Scenario: 非授权角色查看敏感信息
- **WHEN** 非授权角色请求明文数据
- **THEN** 返回脱敏字段或拒绝访问，并写入审计（按策略）

### Requirement: 审计日志
系统 SHALL 对需求文档 13.3 中列举的关键操作写入审计日志，包含变更前后值、操作者、来源与原因等字段。

#### Scenario: 强制闭环
- **WHEN** 管理员执行强制闭环
- **THEN** 必须填写原因，状态变化落库，审计日志记录原因与前后值

### Requirement: 数据管理中心（导入/校验/清洗/关联/修复/导出）
系统 SHALL 支持三类 Excel 模板导入（投诉/满意度/外呼考核），提供行级校验与失败原因；支持清洗、自动关联、匹配失败修复、导出（需求文档 10.4/10.5/10.6/11.1/12.1）。

#### Scenario: 导入投诉数据
- **WHEN** 客服专员上传投诉数据 Excel
- **THEN** 返回导入任务结果（成功条数、失败条数、失败行号与原因），数据进入“待清洗”

### Requirement: 投诉 AI 分析
系统 SHALL 提供投诉 AI 分析能力（需求文档 14.1），输出一级/二级分类、三层根因、责任部门、风险评级、重复投诉标记、置信度、证据片段、整改建议与时限；并支持人工修正与“重新分析覆盖”策略（需求文档 14.2）。

#### Scenario: 低置信度处理
- **WHEN** 置信度低于阈值
- **THEN** 标记需人工确认，并禁止自动批量生成工单（按规则配置）

### Requirement: 整改闭环工单与状态机
系统 SHALL 实现整改工单的主状态与子状态机（需求文档 12.2/12.3），支持生成工单、提交整改、核验、退回、满意度校验、自动退回、闭环与强制终止。

#### Scenario: 满意度校验不通过自动退回
- **WHEN** 工单核验通过且满意度校验不通过
- **THEN** 工单自动退回“整改中”，记录原因与规则命中信息，并写入审计与流程日志

### Requirement: 预警与升级
系统 SHALL 按规则配置计算即将逾期/已逾期并推送通知；已逾期超过 N 个工作日 SHALL 自动升级至部门负责人（需求文档 12.4）。

#### Scenario: 自动升级
- **WHEN** 工单已逾期超过 N 个工作日
- **THEN** 生成升级通知并记录通知日志

### Requirement: 看板与指标口径
系统 SHALL 提供看板指标接口并保证口径统一（需求文档 15.x），支持时间/部门筛选与钻取到明细。

### Requirement: AI 智能问答
系统 SHALL 支持自然语言问答（需求文档 7-扩展页面7），并能返回结论与支撑数据；问答 SHALL 支持历史记录与导出（可分阶段实现）。

### Requirement: 自动化报告
系统 SHALL 支持报告管理（需求文档 7-扩展页面8），包含手动生成、自动生成配置、查看详情、导出、删除，并记录生成状态与操作人。

### Requirement: 系统配置
系统 SHALL 提供投诉分类、根因知识库、部门与权限、智能体规则配置能力（需求文档 9.x），并要求配置变更可审计、可版本化。

## MODIFIED Requirements

### Requirement: 前端对接接口
系统 SHALL 提供与前端现有调用路径一致的 API（优先对齐 /data/*、/analysis/*、/workorder/*、/dashboard/overview、/qa/ask、/report/*、/system/*、/notification/*、/logout），以降低联调成本。

## REMOVED Requirements
